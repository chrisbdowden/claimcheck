# ClaimCheck API

The ClaimCheck Python engine as a web service, for the Lovable front end (`frontend/`).

- **Production:** https://claimcheck-api.vercel.app (Vercel project `claimcheck-api`, root directory `service/`)
- **Interactive docs:** `/docs` (generated by FastAPI)
- **Stateless:** nothing is stored; review decisions stay in the browser
- **Synthetic data only.** Don't send real employee or company data

## Endpoints

| Method | Path | Returns |
| --- | --- | --- |
| GET | `/api/health` | status, whether live AI is configured, limits, the 10 rules |
| GET | `/api/policy` | default policy in the front end's `Policy` shape |
| GET | `/api/sample` | the bundled 1,937-line synthetic dataset (with `planted_issue` answer key) and policy |
| POST | `/api/analyze` | flagged lines, findings, summary, and accuracy when an answer key is present |

`POST /api/analyze` body:

```json
{
  "source": "bundled",
  "lines": null,
  "policy": null,
  "use_ai": false
}
```

- `source`: `"bundled"` (the sample) or `"upload"` (then `lines` is required: the front end's `ExpenseLine[]`)
- `policy`: optional, the front end's `Policy` shape; defaults to `/api/policy`
- `use_ai`: request live AI review (falls back to rules only when unavailable or limited; see `notes`)

Response, abridged:

```json
{
  "mode": "offline",
  "ai": {"requested": false, "used": false, "model": null, "calls": 0},
  "notes": [],
  "summary": {"lines_reviewed": 1937, "lines_flagged": 100, "high_severity": 43,
              "dollars_reviewed": 284863.14, "dollars_flagged": 15573.4,
              "by_severity": {"High": 43, "Medium": 40, "Low": 17},
              "flags_by_rule": {"exact_duplicate": 16, "...": 0}, "seconds": 1.1},
  "flagged": [{"line": {"line_id": "L1892", "...": "..."},
               "findings": [{"rule": "exact_duplicate", "severity": "High",
                             "explanation": "Same $289.59 at Harborview Suites ...",
                             "relatedLineIds": ["L1500"]}],
               "severity": "High",
               "reason": "Same $289.59 at Harborview Suites ..."}],
  "evaluation": {"per_rule": [], "rule_totals": {}, "tx_totals": {}},
  "policy": {},
  "limits": {},
  "cached": false
}
```

`planted_issue` is the evaluation answer key (rule IDs, joined with `|` when a line has more than one). The engine never reads it for detection.

## Live AI limits

Live AI uses Claude (`claude-haiku-5-5`) when `ANTHROPIC_API_KEY` is set in the Vercel project. Every limit falls back to rules only and says why in `notes`:

| Limit | Default | Env var |
| --- | --- | --- |
| Lines per analysis | 5,000 | `CLAIMCHECK_MAX_LINES` |
| Lines per AI analysis | 2,500 | `CLAIMCHECK_AI_MAX_LINES` |
| AI runs per visitor | 3 per 10 min | `CLAIMCHECK_AI_PER_VISITOR`, `CLAIMCHECK_AI_WINDOW_MINUTES` |
| AI runs per hour (per instance) | 20 | `CLAIMCHECK_AI_PER_HOUR` |
| AI time budget | 40 s (unchecked lines get the keyword check) | `CLAIMCHECK_AI_SECONDS` |

Rate limits are per server instance (best effort). The hard backstop is the monthly spending limit on the Anthropic account. Identical requests are answered from a short-lived cache and don't count against the limits. Visitor IDs are hashed; raw IPs aren't stored.

## Develop

```bash
python scripts/sync_service.py          # copy src/ and data/ into service/ (run after engine changes)
cd service
pip install -r requirements.txt pytest httpx
python -m pytest -q                     # 13 tests, fake AI client, no network
uvicorn index:app --reload              # http://127.0.0.1:8000/docs
```

`service/claimcheck_engine/` and `service/data/` are generated; edit `src/` and `data/`, then re-run the sync script. CI fails if the copy drifts.
